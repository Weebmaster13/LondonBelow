# Asset Execution Governance Serialization

Serialization provides deep copies for state, diagnostics, and snapshots. It rejects functions, threads, userdata, cycles, instance-shaped tables, unsafe markers, oversized strings, excessive depth, and excessive node counts.

Serialization is metadata-only. Phase 81 integration-readiness declarations use the same safe-copy and unsafe-marker rules as governance records. Phase 82 proves nested unsafe metadata rejection and returned-copy isolation for declarations, runtime limits, diagnostics, and snapshots. Phase 83 authorization-readiness declarations use the same copied serialization boundary and reject unsafe nested metadata before health validation can pass. Phase 84 expands forbidden marker rejection for approval, rejection, permission, routing, dispatch, scheduler, orchestration, and execution contamination in values, keys, and nested metadata. Serialization never stores live subsystem handles and never creates asset loading, runtime routing, authorization, permission, approval, rejection, dispatch, queue, scheduler, orchestration, or execution surfaces.
